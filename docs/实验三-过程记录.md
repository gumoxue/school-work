## 一、任务 1：Git 基础

### 三区模型

```
工作区 --git add--> 暂存区 --git commit--> 本地仓库
   ^                                          |
   +---------- git checkout -- / git reset ----+
```

### 六个核心命令演练记录

| 命令 | 本次演练结果 |
|---|---|
| `git add` | `docs/git-commands.md` 从工作区进入暂存区（`git status` 由 `??` 变为 `A`） |
| `git commit` | 生成提交 `78dbc54 docs: add git core commands cheatsheet` |
| `git log --oneline` | 查看历史，用于后续定位回滚目标版本 |
| `git diff` | 演示 `checkout --` 前查看工作区改动（新增了"临时改动"行） |
| `git diff --cached` | 提交前审查已暂存的改动（39 行新增） |
| `git checkout --` | 撤销工作区的"临时改动"，`git status` 恢复干净 |
| `git branch` | 创建并切换 `feature/visit-search`，合并后回到 `master` |

命令速查见 [git-commands.md](./git-commands.md)。

## 三、任务 3：分支开发与回滚急救

### 3.1 个人分支开发并合并

```
git checkout -b feature/visit-search     # 新建功能分支
# 在分支实现"关键字 + 科室筛选"
git commit -m "feat: 就诊记录关键字与科室筛选"   # d9d99da
git checkout master
git merge --no-ff feature/visit-search -m "merge: 合并 feature/visit-search 关键字与科室筛选功能"  # 97b5433
```

分支验证：关键词"糖尿病"→1 条；科室"心血管内科"→2 条；无匹配时显示空状态。
截图：`screenshots/03-filter.png`

* 6cac37b style: 就诊记录表格响应式与悬停交互优化

### 3.2 回滚急救演练

1. **制造故障**：将详情页 `visit.patientName` 误改为 `visit.patient.name`，提交 `d1b688d`。
2. **观察翻车现场**：访问详情页白屏，控制台报错
   `Cannot read properties of undefined (reading 'name')`。
   截图：`screenshots/04-broken-detail.png`
3. **定位好版本**：`git log --oneline` 找到上一个正常版本 `97b5433`。
4. **现场急救**：`git reset --hard 97b5433`，丢弃坏提交。
5. **验证恢复**：详情页恢复正常，控制台无错误。
   截图：`screenshots/05-after-rollback.png`

**回滚前后对比**：`04-broken-detail.png`（白屏）↔ `05-after-rollback.png`（正常）。

## 五、心得与反思

- **为什么说"没有 Git 的 vibe coding 是裸奔"**：AI 改动快且可能不可预期，本次详情页被改坏就是实例。若没有 Git，只能凭记忆手工改回；有 Git 时 `git log --oneline` 定位 + `git reset --hard` 一条命令即可在数十秒内恢复。Git 是 AI 协作的"安全气囊"。
- **规范提交的价值**：约定式前缀（feat/fix/style/docs）让历史一眼可读，回滚时能快速判断哪个版本是"好版本"。
- **分支隔离**：在 `feature/visit-search` 上开发，即使失败也不影响可交付的 `master`。
